# ผลทดสอบความสามารถขุนพลทั้ง 25 ตัว

Unit test ที่เรียกฟังก์ชันของ game engine ตรงๆ (ไม่ผ่านเซิร์ฟเวอร์ ไม่ผ่าน socket) โดยจำลอง prompt ให้ตอบอัตโนมัติตามสคริปต์ที่กำหนดไว้ ทำให้ทดสอบความสามารถแต่ละตัวได้แบบเจาะจงและแม่นยำ

**วิธีรัน:** `node test_generals.mjs` (รันจากโฟลเดอร์ `webapp/` ไม่ต้องเปิดเซิร์ฟเวอร์ก่อน)

**ผลล่าสุด: ผ่าน 25/25**

## วิธีที่ทดสอบ

เกมจริงทำงานผ่าน Socket.IO: ผู้เล่นกดปุ่ม → เซิร์ฟเวอร์ถามกลับ (prompt) → ผู้เล่นตอบ → เซิร์ฟเวอร์คำนวณผล การทดสอบแบบนี้ตรงๆ ผ่านเบราว์เซอร์จริงทำได้ แต่ควบคุมยาก (ต้องคลิกเอง, ผลไม่แน่นอนถ้าใช้บอทสุ่ม) จึงเขียน **unit test ที่ตัด Socket.IO ออกไปทั้งหมด** แล้วเรียกฟังก์ชันของ engine ตรงๆ แทน โดยมี 3 ส่วนหลัก:

### 1. จำลองห้อง/ผู้เล่นแบบง่าย (ไม่ผ่าน lobby จริง)

ใช้ `createRoom()` / `createPlayer()` ของเกมจริงตรงๆ แล้วเซ็ตค่าที่ต้องการเอง เช่น กำหนดขุนพลแม่ทัพ/รองแม่ทัพ, การ์ดในมือ, จำนวนทหารราบ — โดยไม่ต้องผ่านขั้นตอนสุ่มจั่วขุนพล/แจกไพ่แบบเกมจริง (เพราะแบบนั้นควบคุมผลไม่ได้)

```js
const room = makeRoom();
const attacker = addPlayer(room, 'g9', { hand: ['s_attack'] }); // ลิโป้ ถือการ์ดโจมตี
const defender = addPlayer(room, 'g99_none', { infantry: 5 });  // ไม่มีการ์ดป้องกัน
```

### 2. "หลอก" ระบบถาม-ตอบ (mock io)

เกมจริงเวลาต้องถามผู้เล่น (เช่น "จะป้องกันไหม", "เลือกเป้าหมาย") จะยิง event `prompt:show` ผ่าน `io.to(socketId).emit(...)` แล้วรอผู้เล่นตอบกลับ ในเทสเราแทนที่ `io` ด้วยของปลอมที่**ตอบเองอัตโนมัติ**ตามฟังก์ชันที่กำหนดไว้ล่วงหน้า:

```js
const ctx = makeCtx(room, (prompt) => {
  if (prompt.kind === 'chooseTarget') return { choice: someBystander.id };
  if (prompt.kind === 'yesNo') return { yes: true };
  return null; // ไม่ตอบ = ปฏิเสธ/ข้าม
});
```

ฟังก์ชันนี้จะถูกเรียกทุกครั้งที่ engine เปิด prompt ขึ้นมา ทำให้ทดสอบสถานการณ์ต่างๆ ได้ตรงจุด (เช่น บังคับให้ตอบ "ใช่" เพื่อดูว่าเอฟเฟกต์ทำงานถูกไหม)

### 3. เรียกฟังก์ชันจริงของ engine แล้วเช็คผลลัพธ์

เรียกฟังก์ชันที่ตรงกับความสามารถนั้นๆ ตรงๆ (เช่น `fireOnAttackSuccess`, `fireOnAttacked`, `performGeneralAbilityAction`) แล้วใช้ `assert` เช็คว่าค่าที่ควรเปลี่ยน (มือ, ทหารราบ, กองเสบียง ฯลฯ) เปลี่ยนถูกต้องตามที่การ์ดเขียนไว้จริง เช่น ตัวอย่างลิโป้:

```js
const result = await performAttack(ctx, attacker, defender, 'card', cardInstanceId);
assert.equal(defender.infantry, 3, 'ควรเสียทหารราบ 2 คน ไม่ใช่ 1');
```

ทำแบบนี้ครบทั้ง 25 ตัว แต่ละตัวเลือกเรียกฟังก์ชันที่ตรงกับประเภทความสามารถของมัน (trigger ตอนโจมตีสำเร็จ, ตอนถูกโจมตี, ตอนเสียทหารราบ, ตอนต้นตา/ท้ายตา, หรือ action ที่กดปุ่มใช้เอง) ข้อดีคือรันซ้ำได้เร็ว (ไม่ถึงวินาที) และผลไม่สุ่ม เทียบกับการเล่นจริงหรือใช้บอทสุ่มที่ต้องรอหลายรอบกว่าจะเจอสถานการณ์ที่ต้องการทดสอบ

## หมายเหตุ

- นี่คือ **unit test** เฉพาะ logic ความสามารถ ไม่ได้แทนที่ `bot_test.mjs` ที่ทดสอบทั้งเกมจริง (setup, เทิร์น, prompt, เงื่อนไขชนะ) ผ่าน socket จริงด้วยบอทสุ่ม — ใช้เสริมกัน
- หลายเทสในนี้ช่วยล็อคบั๊กที่เจอระหว่างเล่นทดสอบจริงไว้ไม่ให้กลับมาอีก เช่น การจัดเรียงการ์ดกลับด้านของเขาเฉียว, ต้นทุนที่ควรบังคับของเตียวก๊ก, เงื่อนไขเสียทหารราบของซุนกวน, และการออกแบบใหม่ของโยจิ๋น (พาสซีฟ vs ต้องกดปุ่ม)
- แนะนำให้รันชุดนี้ซ้ำทุกครั้งที่แก้โค้ดใน `server/src/engine/` เพื่อเช็คว่าไม่มีอะไรพังตามมา
